今年我写给 Agent 的字，可能比写给任何一个人的都多。一开始我把它当成聊天：想到哪说到哪，说错了再纠正。后来发现这样效率很低，就像隔着一条街喊话。

真正好用的方式，更像是写信。一封要寄很远、对方收到以后没法回来问你的信。

## 一封好信的结构

我现在给 Agent 派活，基本是这样一个顺序：

1. **先说结果**：做完以后，世界应该变成什么样子。
2. **再说边界**：哪些文件可以动，哪些绝对不能碰。
3. **然后是线索**：我已经知道的事、我怀疑的地方、以前踩过的坑。
4. **最后是验收**：怎样才算做完，用什么命令验证。

<PullQuote>写给 Agent 的信，读者其实是两个人：它，和三个月后的你自己。</PullQuote>

## 不要写「帮我优化一下」

「优化一下」是最糟糕的一句话。它把所有判断都留给了收信人，而收信人对你的项目、你的审美、你的老板一无所知。

比较好的写法是把「优化」翻译成可以检查的东西：首屏少于一秒；这个函数不超过四十行；不要新增依赖。写不出来的时候，通常说明我自己也还没想清楚。

## 回信

好的 Agent 也会「回信」：它做完以后会告诉你改了什么、没做什么、哪里不确定。我会把这些回信收进一个文件夹，过一段时间翻一翻，很多重复出现的问题，就是该写进规则里的东西。

这有点像海边捡漂流瓶。大部分瓶子里都是同样的几句话，但偶尔会有一封，让你决定改掉一个用了很多年的习惯。
